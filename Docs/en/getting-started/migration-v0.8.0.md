# Migrate from FrameKit v0.7.0 to v0.8.0

This guide covers the release path from the tags `v0.7.0` to `v0.8.0`. The
`create-framekit-v0.7.1` tag was an intermediate CLI release in that path; it
does not replace the required runtime update to `@mauriciodmo/framekit@0.8.0`.

It is for existing FrameKit projects, projects generated by
`create-framekit`, template authors, and consumers of the public API.

## Quick migration checklist

### Required

- [ ] Update `@mauriciodmo/framekit` to exactly `0.8.0`.
- [ ] Reinstall dependencies and refresh the lockfile.
- [ ] Run `framekit generate`, `framekit check`, and `framekit build`.
- [ ] Review any generated changes before committing them.

### Optional

- [ ] Add a `src/brand` catalog and `/brand` route.
- [ ] Use the generated project's `src/profile.ts` convention.
- [ ] Update official skills with `create-framekit@0.8.0`.
- [ ] Adopt the new Studio UI behavior and clipboard export.

## Required migration

### 1. Update the runtime package

Update the runtime in every existing project. With pnpm:

```bash
pnpm add @mauriciodmo/framekit@0.8.0
pnpm install
```

With npm:

```bash
npm install @mauriciodmo/framekit@0.8.0
npm install
```

The package update is mandatory for 0.8.0. Keep the existing Next.js, root
layout, stylesheet, and editor route integration unless you are adopting one
of the optional features below. See [Integrate Into an Existing Next.js
Project](./existing-project.md) for the supported integration shape.

### 2. Regenerate, validate, and build

Run these commands from the project root:

```bash
pnpm framekit generate
pnpm framekit check
pnpm framekit build
```

`generate` refreshes both the template and brand registries. `check` validates
template definitions and their resolved locales. `build` runs `check` again
before the Next.js production build. The generated files under
`src/generated/framekit/` are disposable output; do not edit them by hand.

With npm, use the equivalent commands:

```bash
npm exec -- framekit generate
npm exec -- framekit check
npm exec -- framekit build
```

## Existing Studio integration

Existing integrations remain compatible. A route that already renders
`<FrameKitStudio templates={templates} />` can remain unchanged. The new
`brands` input is optional; when it is omitted, Studio uses an empty brand
catalog. There is no requirement to add a brand route or a `src/brand`
directory.

For public entry points and types, see the [Public API reference](../reference/public-api.md).

## Optional: the brand catalog

### Add the `src/brand` contract

Create a `src/brand` tree only if the project needs a browsable catalog of
reusable brand components. FrameKit discovers it recursively. A component leaf
has this shape:

```text
src/brand/<domain>/<component>/
├── README.md
├── component.tsx
└── preview.tsx
```

The discovery contract is:

- Every non-hidden path segment uses lowercase letters, numbers, and hyphens:
  `^[a-z0-9]+(?:-[a-z0-9]+)*$`.
- Directories beginning with `.` or `_` are ignored.
- A directory containing `component.tsx` is a leaf and must also contain
  `preview.tsx` and `README.md`.
- The first non-empty prose paragraph in the leaf README becomes the catalog
  description. Keep it useful without relying on a heading or list.
- `preview.tsx` must default-export the representative React preview that
  Studio loads. The generated catalog does not edit component props.

See [Brand Components](../guides/brand-components.md) and the [brand catalog
reference](../reference/brand-catalog.md) for the full contract.

### Generated registry

After `framekit generate`, FrameKit writes:

```text
src/generated/framekit/brands.ts
```

This generated, project-local module provides `brands`, `brandManifest`, and
`brandRegistry`. It is overwritten by generation and is not a package export;
do not edit it manually. If `src/brand` is absent, the generated brand list is
empty.

### Add the `/brand` route

For an App Router project with the `@framekit/generated/*` alias, add a client
catch-all route such as `src/app/brand/[[...slug]]/page.tsx`:

```tsx
'use client'

import { brands } from '@framekit/generated/brands'
import { FrameKitStudio } from '@mauriciodmo/framekit/studio'

export default function BrandPage() {
  return <FrameKitStudio brands={brands} />
}
```

The catalog is browsable at `/brand/<slug>`. The existing editor route can
continue to pass only `templates`. For template authoring and generated
registries, see [Template Authoring](../guides/template-authoring.md).

## Optional: `src/profile.ts` in generated projects

Projects newly generated by `create-framekit` include an optional
`src/profile.ts` starting point:

```ts
export const profile = {
  companyName: 'Your company',
} as const
```

Use it for public, reusable company information that may appear in images.
Its object shape is intentionally flexible: templates and skills may consume
the whole object or selected exports. It is a project convention, not a
FrameKit package API, and existing projects do not need to add it.

## Additive API and compatibility notes

The 0.8.0 public API additions include:

- `FrameKitStudioBrand`, exported from `@mauriciodmo/framekit/studio`.
- The optional `brands` input on `FrameKitStudio`.
- Optional `copyPng` in `EditorMessages` for localizing the copy button.

The generated `brands`, `brandManifest`, and `brandRegistry` values remain
project-local generated output, not package exports. There are no confirmed
breaking changes to the public API between the relevant tags. Existing
consumers should still run the required generation, validation, and build
commands above to catch project-specific issues.

## Optional UI and CLI changes

No application changes are required to receive these improvements after the
package update:

- Studio can copy the current frame as a PNG when the browser supports image
  clipboard writes.
- Folder expansion in navigation is persisted in browser storage.
- The Studio sidebar can be collapsed and expanded.
- `framekit dev` retries the next port when the requested port is already in
  use, and reports the port it actually bound to.
- Generation output is now English, for example `FrameKit: 3 templates`,
  instead of the previous `plantilla(s)` text.

The clipboard action still depends on browser clipboard support; downloading
PNG remains available independently.

## Skills in generated projects

Official skills were renamed from `framekit-*` to `fk-*`. The public skill
names include `fk-setup`, `fk-studio`, and `fk-templates` (with the brand
workflow available as `fk-brand`).

From the project root, update the official skills with the 0.8.0 CLI:

```bash
pnpm dlx @mauriciodmo/create-framekit@0.8.0 update-skills
```

The npm equivalent is:

```bash
npx @mauriciodmo/create-framekit@0.8.0 update-skills
```

This command replaces the official skill directories, removes the known legacy
directories `framekit-project-setup`, `framekit-studio-usage`, and
`framekit-template-creation`, and preserves custom skill directories. It does
**not** update application files, templates, routes, or package manifests. Make
those project changes manually, then rerun the required FrameKit commands.
