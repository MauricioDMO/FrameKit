# Issue #11 — Source Migration Command

- **GitHub issue:** https://github.com/MauricioDMO/FrameKit/issues/11
- **Status:** Closed as not planned; GitHub issue state is authoritative.
- **Release:** No version preselected.

## Decision

FrameKit will not add a `framekit migrate` command for the canonical contract
transition in issues #3–#9. The required changes replace semantic TypeScript and
TSX fragments, where automatic rewriting would be complex and unsafe relative
to the small number of maintained templates and absence of external users.

## Consequences

- Issues #3–#9 update the repository templates, starter, tests, and generated
  consumers directly as part of their implementation.
- `framekit check` validates only the canonical contract and reports invalid
  definitions; it does not rewrite source files.
- English and Spanish rolling `migration-next.md` guides provide the cumulative
  manual author steps for each contract change.
- There are no version-based `--from`/`--to` flags, codemod framework, dry-run,
  JSON migration report, migration exit-code taxonomy, or source-formatting
  guarantees.
- Generated files are regenerated by their owning commands rather than migrated.
- A future automatic migration requires a new issue based on a shipped source
  contract, real affected users, and transformations proven deterministic and
  meaningfully less costly than documented manual edits.

## Closure steps

1. Remove the current `framekit migrate` proposal from the conceptual CLI plan.
2. Record this decision in the execution index and related compatibility and
   field plans.
3. Replace the GitHub issue proposal with this decision and close it as
   `not planned`.

No runtime implementation, public documentation update, changelog entry,
migration-guide entry, generated artifact, test, or release assignment is
required for this closure-only issue.

## Verification owned by active issues

- Each issue from #3 through #9 updates all repository-owned templates and the
  generated starter to its canonical contract.
- `framekit check` and focused tests reject the obsolete shape after each
  owning issue lands.
- Each breaking issue documents exact manual steps in both rolling
  `migration-next.md` guides.
- Generated output is recreated and verified rather than source-migrated.

## Out of scope

- TypeScript or TSX codemods and arbitrary renderer rewriting.
- Automatic metadata values or numeric-string conversion.
- Runtime compatibility, aliases, coercion, or localStorage migration.
- Future portable-document schema migration.
- Selecting a release version.
